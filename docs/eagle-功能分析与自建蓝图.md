# Eagle 4.0 功能分析与自建蓝图

> 调研对象：`D:\软件\Eagle\Eagle`（Eagle 4.0.0，build 20251008，Electron 22.3.7）
> 你的资料库：`E:\eagel资源库\素材.library`（约 150 个条目：105 jpg / 34 png / 10 mp4 / 1 webp，主要收藏 AI 创作与排版素材）

---

## 一、Eagle 的技术架构（它是什么做的）

| 层 | 技术 |
|---|---|
| 壳 | Electron 22（Chromium 108），界面全是 Web 技术 |
| 核心逻辑 | bytenode 编译成 V8 字节码（.jsc），**不开源，无法直接读源码** |
| 图像处理 | ImageMagick（Magick.dll）—— 缩略图、格式转换、调色板 |
| 截图 | NiuniuCapture（区域/窗口/全屏截图的商用 SDK） |
| Office 缩略图 | libExcel / libPPT / libWord + electron-edge-js（.NET 互操作） |
| 图像解码 | 自带 jpg / png / gif / heif / tiff / RAW / PSD 等解析模块 |
| 搜索 | nodejieba 中文分词 + 拼音检索（pinyinlite） |
| 文件监听 | nsfw（监控外部文件变化、自动导入） |
| 颜色 | delta-e 色差算法 + quantize（提取主色调板，用于颜色筛选） |
| 对外接口 | 本地 HTTP API（设置里有 developer.apiToken）+ 浏览器扩展 + MCP（4.0 新增，接 AI 工具） |

**结论：架构上没有任何你做不出来的黑科技，全部是成熟方案的组合。** 它的壁垒是多年打磨的交互细节，而不是技术。

## 二、完整功能地图（从程序内 1800+ 条界面文案与全部快捷键提取）

### 1. 资料库管理
- 多资料库，一键切换（`.library` 开放格式，见第三节）
- 资料库密码锁（全局锁定 Cmd+Alt+L，文件夹也可单独加密）
- 自动备份 / 恢复

### 2. 组织体系（Eagle 的核心抽象：一个文件可同时属于多个文件夹）
- 文件夹树（可无限嵌套，文件夹上还能挂标签）
- **智能文件夹**：把一组筛选条件存成虚拟文件夹
- 标签系统：标签群组、常用标签、历史标签、复制/粘贴标签
- 评分（0-5 星）
- 注释（annotation，可写富文本标注）与备注（note）
- 来源 URL（记录每个素材从哪来的）
- 固定视图：「全部 / 未分类 / 未标签 / 最近添加 / 随机 / 全部标签 / 回收站」

### 3. 收集与导入
- 浏览器扩展：网页图片批量抓取、整页挑选收藏
- 内置浏览器：不用离开 Eagle 就能浏览网页存图
- 截图收集：区域/窗口/全屏（全局快捷键 Ctrl+Alt+E），可自动打标签
- 剪贴板监听收集
- 本地文件夹导入、拖放导入
- URL 链接导入（存为书签或直接下载）
- 站点专用抓取：Pinterest / ArtStation / 花瓣网
- 自动导入：监听某个文件夹，有新文件自动收进库
- `.eaglepack` 素材包（把素材连元数据打包分享）

### 4. 浏览与视图
- 4 种布局：网格 / 瀑布流 / 自适应行 / 列表
- 缩放滑杆（调整缩略图大小）、悬停放大预览
- GIF 悬停播放、视频播放器（逐帧步进、变速、循环短视频、截取封面帧）
- 字体文件预览（ttf/otf/ttc，含已安装/未安装筛选）
- PSD/AI/Sketch/XD/Word/PPT/Excel 缩略图与预览
- 大图查看器：旋转、翻转、裁剪、多图合并、图像标注
- 信息面板（Inspector）：尺寸、大小、EXIF（相机/光圈/快门/ISO/焦距）、调色板、来源链接
- 视觉辅助：灰度模式（看排版对比度）、幻灯片放映

### 5. 搜索与筛选（Eagle 最强的一块）
- 关键词搜索：中文分词 + 拼音匹配 + 快速搜索浮窗（Ctrl+J）
- 筛选器（可叠加、可存为智能文件夹）：标签、颜色（按提取的主色）、形状（横/竖/方/细长全景）、评分、添加日期、修改日期、格式、文件大小、分辨率、时长、注释、备注、网址、相机、BPM、字体、**AI 语义搜索**（描述"黑色的猫"直接找图）
- **以图找图**：库内相似图 + Google/Bing/Yandex/TinEye/SauceNAO/百度/搜狗

### 6. 整理工具
- **动作（Actions）**：自定义快捷键触发一连串操作（加文件夹+加标签+评分一步完成）
- 批量：重命名、打标签、移动
- 重复文件扫描：完全相同 / 视觉相似（128MB 以下），向导式合并去重
- 回收站（软删除）

### 7. 导出与输出
- 导出到计算机 / 指定格式或尺寸导出 / 导出 CSV
- 复制：文件路径、Eagle 链接（`eagle://` 协议）、Base64、缩略图、文件名

### 8. 外观与偏好
- 深色/浅色主题、界面配色自定义
- **47 项"习惯"设置**：滚轮行为（缩放/滚动）、双击行为、悬停放大开关、默认视图模式、GIF 自动播放等 —— 这正是"每个人用起来舒服点不一样"的地方
- 代理设置、通知音效、开机自启

## 三、数据格式（自建版本最该兼容的部分）

```
素材.library/
├── metadata.json          ← 库结构：文件夹树、智能文件夹、标签群组
├── images/
│   └── MH7G2SR2UIMTX.info/          ← 每个条目一个文件夹
│       ├── metadata.json            ← 条目全部元数据
│       ├── 原文件.xxx
│       └── 原文件_thumbnail.png
├── tags.json              ← 常用标签、历史标签
├── actions.json           ← 自定义动作
├── saved-filters.json     ← 保存的筛选器
└── mtime.json / backup/
```

条目 metadata.json 实测字段：
```json
{
  "id": "MH7G2SR2UIMTX",          // 12 位随机大写字母数字
  "name": "即梦AI - 一站式AI创作平台",
  "size": 4340543, "btime": 1761467177567, "mtime": 1761467179571,
  "ext": "mp4", "tags": [], "folders": ["MH7FDY4V7GZA0"],   // 多对多！
  "isDeleted": true, "url": "https://...",
  "annotation": "",
  "width": 2944, "height": 1664, "duration": 5.016667,
  "palettes": [ {"color": [49,68,42], "ratio": 44}, ... ]    // 主色提取
}
```

库级 metadata.json 实测字段：
```json
{
  "folders": [ {"id", "name", "description", "children": [...], "tags": [], "password": ""} ],
  "smartFolders": [], "quickAccess": [], "tagsGroups": []
}
```

> **关键设计点：文件与文件夹是多对多关系**（`folders` 是数组），文件本体永远只存一份在 `images/` 里。这是 Eagle 能"一个素材进多个分类"的核心。

## 四、自建版本建议

### 技术选型
| 方案 | 优点 | 缺点 |
|---|---|---|
| **Electron + Vue/React**（推荐） | 和 Eagle 同架构，Web 生态最全，缩略图/瀑布流好做 | 打包体积大、内存占用高 |
| Tauri (Rust + Web) | 体积小、内存低，前端一样写 | 原生能力要自己写 Rust，图像处理生态弱一些 |
| 本地 Web 服务 + 浏览器 | 最简单，随便什么语言 | 没有全局快捷键/截图/文件监听等系统集成 |

既然你已经被 Eagle "内存大、卡" 之类的问题困扰的话…… 注意：Electron 本身不省资源。如果性能是你主要痛点，选 Tauri；如果开发速度和生态优先，选 Electron。

### 核心模块清单（按必要性排序）
1. **存储层**：直接沿用/兼容 Eagle 的 `.library` 格式（或导入器），条目 = 文件夹 + metadata.json，文件夹多对多
2. **缩略图服务**：sharp（Node）或 image-rs（Rust），后台队列生成，支持 psd/视频抽帧
3. **浏览器 UI**：虚拟滚动瀑布流/网格 + 多选 + 拖拽
4. **元数据面板**：标签、评分、注释、来源 URL、调色板
5. **筛选/搜索**：SQLite FTS5 全文搜索 + 标签/格式/尺寸/日期筛选（颜色筛选用调色板数据）
6. **收集**：剪贴板监听、拖放导入、浏览器扩展（可后续做）
7. 进阶：智能文件夹、动作、相似图去重（感知哈希 pHash）、以图找图

### 可以比 Eagle 更好的方向（典型痛点）
- 启动速度和内存：按需加载缩略图、SQLite 替代全量 JSON 扫描
- 视频素材管理（你库里有 mp4）：抽帧条、关键帧预览
- AI 能力本地化：用本地 CLIP 模型做语义搜索，不用等官方 AI 服务
- 完全开放的数据 + 开源，不怕停更

## 五、给自建项目的第一步

1. 先明确：你用 Eagle 最不舒服的 3 个点是什么？（性能？交互？某个功能缺失？）
2. 用脚本把现有 `素材.library` 读一遍，验证数据格式的兼容策略
3. 做一个最小原型：浏览 + 标签 + 搜索，跑通再堆功能
